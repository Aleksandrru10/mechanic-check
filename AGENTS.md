# Правила проекта для Codex

## Проект

Это Android-приложение «Механик-чек» для создания и выполнения чек-листов ремонта автомобилей.

Рабочая папка проекта: `E:\Codex\mechanic-check`.

Основные исходники интерфейса находятся в `app/assets/`, Android-код — в `app/src/`, версия приложения задаётся в `app/AndroidManifest.xml`.

Перед изменением формы или публикацией обновления прочитать `ERRORS.md`: там записаны подтверждённые ошибки и проверки, которые нельзя пропускать.

## Подключённый GitHub

## Обязательное правило публикации

После каждого согласованного изменения, которое готово к использованию:

1. Обновить версию в `app/AndroidManifest.xml` и увеличить `versionCode`.
2. Обновить `ROADMAP.md`.
3. Собрать подписанный APK командой `python build.py`.
4. Выполнить `python release.py prepare --notes "Описание изменений"`: команда копирует итоговый APK в корень и создаёт `latest.json` в формате, который читает установленное приложение.
5. Перед публикацией выполнить `python release.py verify`. Обязательные имена полей `latest.json`: `schema`, `apk`, `versionName`, `versionCode`, `size`, `notes`, `sha256`, `minSdk`, `packageName`. Не заменять `apk` на `file` и `size` на `bytes`.
6. Проверить `node --check app/assets/mechanic.js`, если менялся JavaScript.
7. Закоммитить исходники, `latest.json` и APK.
8. Выполнить `git push origin master`.
9. Проверить, что `latest.json` и APK доступны из удалённого GitHub Raw и схема `latest.json` не изменилась.
10. В ответе пользователю сообщить версию, факт загрузки на GitHub и ссылку на APK или репозиторий.

Не считать задачу завершённой, пока готовая версия не загружена на GitHub, если пользователь явно не попросил оставить изменения только локально.

## Безопасность и файлы сборки

- Не добавлять в Git содержимое `private/`, пароли, ключи подписи и временные файлы.
- Не добавлять временные каталоги `build/`, `dist/` и `build-log.txt`, если они не нужны для отдельной задачи.
- Для обновления использовать тот же ключ подписи, чтобы приложение могло обновляться поверх установленной версии.
- Перед публикацией сверять SHA-256 APK с полем `sha256` в `latest.json`.

## Текущие функциональные направления

- Чек-листы ремонтных работ и финальная проверка автомобиля.
- Таймер работы, заметки и пользовательские пункты.
- Модельный ряд JETOUR и регламенты ТО-1 — ТО-8.
- История работ, редактирование, экспорт и резервное копирование — следующие направления развития.

## Стиль изменений

Пользователь общается на русском языке. В интерфейсе использовать понятные русские подписи. После заметного изменения проверять основной пользовательский сценарий и кратко описывать результат в ответе.
