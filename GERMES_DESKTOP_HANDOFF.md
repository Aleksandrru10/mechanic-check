## Цель приложения

Android-приложение для механика: выбор автомобиля, регламентного ТО, автоматическое создание чек-листа работ, отметки выполнения, финальная проверка и история обслуживания.

Пользователь выбирает марку, модель, двигатель/коробку/привод (если это требуется), затем ТО-1…ТО-8. Для заводского регламентного ТО поля «Что делаешь» и «Название работы» должны быть скрыты или недоступны. Для варианта «Другая» автомобиль вводится вручную, а для нерегламентной работы доступны название и тип работы. Если выбрана марка и модель из каталога, верхнее поле свободного ввода автомобиля не должно требоваться при создании чек-листа.

## Что уже реализовано

- Каталоги JETOUR, TENET, FAW/BESTUNE и CHERY; актуальные российские модели плюс сохранённые архивные модели.
- Регламенты ТО-1 — ТО-8 с выбором варианта двигателя, коробки и полного привода там, где это влияет на состав работ.
- Подробные карточки с моторными маслами, жидкостями коробок, агрегатов AWD, интервалами и оговорками по VIN.
- Чек-листы обычного обслуживания, таймер, заметки, пользовательские пункты, история, экспорт и резервное копирование.
- Финальная проверка автомобиля и контрольные вопросы механика: масло/фильтр, сливная пробка, прокачка и герметичность после замены жидкостей. Не добавлять в финальную проверку задачи приёмщика «ошибки проверены повторно» и «пробный заезд».
- Календарь работ: дата, автомобиль, выбранное ТО и история выполненных работ.
- Условная логика формы: модельные автомобили не должны требовать свободное поле «Автомобиль»; свободное поле остаётся только для «Другая».
- Официальные позиции деталей и расходников CHERY для ARRIZO 8, TIGGO 7L и TIGGO 9: все ТО-1 — ТО-8.

- Для TENET A8 нет опубликованной полной сервисной книжки с таблицей ТО, допусками и объёмами.
- Для JETOUR T1 Hybrid официальное руководство не содержит полной плановой таблицы ТО и таблицы заправочных объёмов.
- Для JETOUR X70 свежий официальный PDF содержит пустые таблицы графика ТО и жидкостей.
- Для части вариантов детали, артикулы, тип AWD и фактический объём заливки нужно подтверждать по VIN.
- Новые модели и версии нужно добавлять только после проверки официального руководства или официального калькулятора, не переносить данные от похожей модели.

- `latest.json` — JSON автообновления.

## Обязательный выпуск обновления

Перед выпуском:

1. Прочитать `ERRORS.md`.
2. Проверить JavaScript: `node --check app/assets/mechanic.js`.
3. Увеличить `versionCode` и `versionName` в `app/AndroidManifest.xml`.
4. Обновить `ROADMAP.md` и `SERVICE_DATA_STATUS.md`.
5. Собрать: `python build.py`.
6. Подготовить релиз: `python release.py prepare --notes "Описание изменений"`.
7. Проверить: `python release.py verify`.
8. Сверить SHA-256 APK с `latest.json`.
9. Закоммитить исходники, `latest.json` и APK.
10. Выполнить `git push origin master`.
11. Проверить доступность `latest.json` и APK через GitHub Raw.

Обязательные поля `latest.json`: `schema`, `apk`, `versionName`, `versionCode`, `size`, `notes`, `sha256`, `minSdk`, `packageName`. Не переименовывать `apk` в `file` и `size` в `bytes`.

Не включать в Git каталоги `private/`, ключи подписи, пароли, временные `build/`, `dist/` и `build-log.txt`.

## Передача подписи приложения

Для обновления уже установленных APK GERMES должен использовать тот же закрытый ключ подписи, который лежит в локальной папке `private/` текущего рабочего окружения. Сам файл ключа нельзя помещать в GitHub, этот handoff-файл, чат или APK. Нужно передать GERMES доступ к закрытой папке через защищённый канал или запускать его в том же окружении. Если потерять ключ и собрать новым ключом, Android не установит обновление поверх старой версии: потребуется удаление приложения или новый package name.

## Ошибки прошлых итераций

- Пользователь устанавливал APK, но интерфейс оставался прежним: проверять versionCode, содержимое APK и GitHub Raw, а не только локальную сборку.
- Версия 1.36 не видела обновления: проверять формат и доступность `latest.json` после push.
- Поле «Автомобиль» ошибочно требовалось при выборе марки/модели: тестировать сценарий выбора модельного автомобиля отдельно от «Другая».
- Поля «Что делаешь» и «Название работы» ошибочно оставались видимыми для регламентного ТО: проверять реальный экран и DOM после выбора ТО.
- Не назначать AWD, масла и детали без подтверждения варианта привода/коробки.
- Не превращать количество упаковок из калькулятора CHERY в литры.
